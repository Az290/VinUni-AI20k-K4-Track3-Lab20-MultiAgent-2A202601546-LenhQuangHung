## Failure modes observed
- **Supervisor loop guardrail**: if Researcher/Analyst keep failing (e.g. LLM timeout), the Supervisor still forces `done` once `max_iterations` is hit, so the workflow always terminates with a best-effort (possibly partial) answer instead of hanging.
- **Search returns nothing**: `SearchClient` (offline corpus or Tavily) may return zero sources for an off-topic query. The Researcher then records `"No sources were found"` instead of crashing, and downstream agents degrade gracefully (Analyst/Writer note the missing evidence).
- **LLM call failure after retries**: `LLMClient.complete` retries transient errors (timeout/rate limit) 3x with exponential backoff, then raises `AgentExecutionError`. Each worker agent catches this and falls back to a best-effort output (e.g. Writer stitches together analysis/research notes) rather than aborting the whole run — this is why `failure_rate` can be non-zero while a `final_answer` still exists.
- **Fix applied**: added per-agent try/except around LLM calls with fallback content, plus `CriticAgent` as a cheap deterministic validator that flags citation gaps or too-short answers without spending another LLM call.
